# A2 Buffer 审计与 Debug 隔离

日期：2026-07-13  
状态：已实施生产拒绝边界；legacy 数值路径保留，未声明为生产支持。

## 生产契约

- 默认 `NcnnRepro.ExecutionMode` 为 `ProductionTextureOnly`。
- 固定 `ComputeBuffer` 输入可在推理开始前上传并一次性 materialize 为 Pack4 texture；该输入适配不是 activation fallback。
- `GetOrConvertToBuffer`、`RentScratchTensorFromTexture`、临时 Buffer 分配和 Buffer-to-texture materialization 在生产执行中统一拒绝。
- 失败文本包含 `site`（layer/node）、`blob`、`logical_shape`、`storage_shape`、`layout`、`dtype` 和 `rejected_fallback`。
- `InferResult.GetBufferData` 和公共 `GetBuffer` 已移除。最终用户输出使用 `ReadTextureDataForOutput`，不 materialize ComputeBuffer。
- `GetBufferView`、`TryGetExistingBufferView`、`ExtractBuffer` 仅在 `UNITY_EDITOR` 或 `AIIMAGE_INFERENCE_DEBUG_ORACLE` 编译。

## 编译边界

`AIIMAGE_INFERENCE_DEBUG_ORACLE` 是 Player 中启用 legacy 数值 oracle 的唯一自定义符号；Editor 仍可编译既有 compare/dump 工作流。未定义该符号的 Player 不会编译 InferResult 的 Buffer inspection API。

## 审计清单

| 位置 | API / 路径 | 分类 | 生产结果 |
| --- | --- | --- | --- |
| `NcnnCompute/NcnnRepro.cs` | `GetOrConvertToBuffer`、`RentScratchTensorFromTexture` | legacy Buffer activation 路径 | 统一拒绝 |
| `NcnnCompute/NcnnRepro.cs` | `MaterializeTextureFromBuffer*`、`MaterializeCmdTextureFromBufferView` | legacy Buffer-to-Pack4 | 统一拒绝 |
| `NcnnCompute/NcnnOps.cs` | `TexToBuf`、`BufToTex`、`Pack4ToBufferCHW/CDHW` kernels | conversion primitive | 仅由 DebugOracle/legacy 调用；不是生产 fallback |
| `NcnnLayers/*` | `ExecuteComputeBufferPath`、`ExecuteBuffer` 中的 `GetOrConvertToBuffer` | legacy layer oracle | 首次 Buffer access 失败；不将 capability 标记为 Cmd supported |
| `NcnnRepro.InferResult` | public Buffer readback/inspection | Debug/Oracle | 在 Player 默认构建中不存在 |
| CLIP / SD / MONAI / CodeFormer / YOLO runners | legacy Buffer input、dump 和数值读取 | legacy runner branch | 固定 Buffer 输入可上传；任何后续中间 materialization 被 engine 拒绝；仅已有 Pack4 路径可继续 |

## 自动验证

`Assets/Editor/NcnnProductionPathAuditTests.cs` 验证：

1. 公共 `GetBufferData` / `GetBuffer` 不会重新出现；
2. 生产 guard、完整 tensor contract 诊断和 DebugOracle 编译条件存在；
3. Buffer conversion API 不会逃离 `NcnnCompute` / `NcnnLayers`；7 个已知 legacy runner 的 API 调用次数为固定基线，任何新增调用都会失败；
4. 生产日志包含 `intermediate_buffer_materializations=0`。

## 未支持（仍为拒绝，不是 supported）

- 所有以 `ComputeBuffer` 作为中间 activation/output 的 CLIP text、Stable Diffusion latent/sampler、legacy MONAI buffer patch、YOLO CPU proposal 和 CodeFormer/GFPGAN legacy 分支。固定输入上传不在此限。
- 未实现真实 Pack4 CommandBuffer 的 layer 分支，例如通用 Gemm、LayerNorm、量化、部分 reshape/layout、SDPA/MHA 和部分 3D 分支。
- 输出 texture 的 CPU readback 仅用于用户请求的导出或已有 debug 诊断；不是下游 layer 的数据通路。
