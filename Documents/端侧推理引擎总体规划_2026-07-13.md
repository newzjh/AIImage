# Unity 端侧推理引擎总体规划

日期：2026-07-13  
范围：AIImage 现有 ncnn Vulkan/Unity 复刻，及其作为 AICityRunner、JZ-Segmentation、PharmaDockingMR3 共同端侧推理底座的演进方案。

## 1. 结论与边界

项目不应继续把目标描述为“复刻 ncnn 层”。现有代码已经对 ncnn Vulkan 64 个 layer 建立了 `64/64` 注册入口，且新增了 Sentis/ONNX 结构类入口；但这只说明图可识别，不说明生产 GPU 路径可计算。真正的产品目标应是：

> 一个以 Unity 为宿主、以 Pack4 RenderTexture/TextureArray 与 CommandBuffer 为唯一生产执行存储、可导入 ONNX/ncnn/MNN 模型、可按领域组合医学/游戏/分子插件的端侧推理平台。

核心边界如下：

- 生产推理只允许纹理原生张量。`ComputeBuffer` 仅保留在 `Debug`/数值对照/模型转换验证程序集，不能成为任何正常模型执行的隐式回退。
- 引擎核心不包含 MONAI、VISTA、DICOM、药物化学或游戏业务规则；它只提供模型、图、张量、内核、调度、量化、验证与可观测性。
- ncnn、Sentis 和 MNN 是前端格式/兼容目标，不是三套平行执行器。导入后统一到一个内部图 IR，并由同一个 Pack4 RT/Cmd 后端执行。
- “支持某算子”必须细分为 Import、Shape、RT、Cmd、FP16、INT8、验证七项能力；未具备 Cmd 的算子不能宣称生产可用。
- 医疗场景默认优先准确性、可重复、审计和内存守卫；游戏优先帧预算、异步和降级策略；药物场景优先结构化数据和减少 GPU/CPU 往返。

## 2. 当前基线与主要缺口

### 2.1 已有可复用资产

- `NcnnLayerFactoryRepro` 已注册 96 个入口：官方 Vulkan 64 层与 ncnn/PNNX/Sentis 相关扩展。
- `RepoVkTensorContract` 已开始把 `logicalShape`、`storageShape`、`layoutKind` 与共享资源 owner 绑定；reshape/flatten/squeeze 等 alias 语义不再只依赖名称旁的 shape 表。
- 已有 Pack4 shader 分组：卷积、空间/布局、逐点/归一化、矩阵乘法、Sentis 结构算子等；并已有 RenderTexture 和 CommandBuffer 两类入口。
- CLIP 与 Matting 已进行真实 runner 验证；wholeBrain MONAI 已可完整执行，安全基线 `run46` 的 labelmap 对齐率为 `0.998750372`。

### 2.2 不能被入口覆盖率掩盖的缺口

根据 `Ncnn_Vulkan_Layer_复刻覆盖统计_2026-06-05.md`，大量层仍为 RT/Cmd 部分实现、alias、占位或 legacy：

| 风险等级 | 主要缺口 | 对产品的影响 |
| --- | --- | --- |
| P0 | 通用 Conv/Deconv、Gemm/InnerProduct/MatMul、LayerNorm/Softmax/Reduction、attention、Permute/Reshape 的 Cmd 完整性 | 新模型会在主干上断裂；MONAI 和生成模型的结果/性能不稳定 |
| P0 | Quantize/Dequantize/Requantize、Cast、Packing 的 Pack4 Cmd 真实实现 | 无法交付可信 FP16/INT8 产品路径 |
| P0 | 严格模式缺少统一能力判定与禁止 fallback 的执行门 | “跑通”可能实际走到 Buffer，无法达成弃用目标 |
| P1 | 动态 shape value-flow，NonZero/Compress/GatherND/Scatter，动态 TopK/OneHot | ONNX/Sentis 模型导入成功率受限 |
| P1 | GridSample、RoiAlign、NMS | 检测、分割和视觉游戏模型接入受限 |
| P1 | KV cache、RotaryEmbedding、SDPA/MHA 的泛化 | 端侧语言/多模态/生成式模型受限 |
| P2 | LSTM、随机采样、STFT/DFT/音频 | 音频和时序模型覆盖不足 |

注意：已有 wholeBrain 流程的安全守卫必须保留。实现 Pack4 不能以关闭 `AIIMAGE_MONAI_*` 清理/让步参数为代价。每个 MONAI/VISTA 改动仍先用 `RunMonaiUnityDebug.bat` 进行 probe、小 patch、再全量验证。

## 3. 目标架构

```text
          ncnn param/bin     ONNX / Sentis      MNN model
                 \               |               /
                  +-- Import adapters + model manifest --+
                                                   |
                                      Unified Graph IR + shape IR
                                                   |
                                  Graph optimizer / capability planner
                                                   |
      +---------------------------- Execution plan ---------------------------+
      |                 CommandBuffer Pack4 texture backend                   |
      | Tensor allocator | alias planner | barriers | profiling | cancellation |
      +----------------------------+------------------------------------------+
                                   |                    |
                         Pack4 RT / TextureArray      debug-only Buffer oracle
                                   |
                       Unity render/XR/volume/mesh consumers

  Domain packages: Medical (MONAI/VISTA) | Game (AICityRunner) | Molecule (Docking)
```

### 3.1 核心程序集与职责

建议采用 UPM package + asmdef，而不是继续把所有代码放进应用的 `Assembly-CSharp`：

| 包/程序集 | 公开职责 | 禁止依赖 |
| --- | --- | --- |
| `com.aiimage.inference.core` | Tensor descriptor、IR、模型 manifest、错误码、能力矩阵、生命周期接口 | Unity 场景、业务模型、DICOM |
| `com.aiimage.inference.unitygpu` | Pack4 storage、RT pool、CommandBuffer recorder、GPU fence、profiling | ncnn 文本解析、医学/游戏业务 |
| `com.aiimage.inference.kernels` | HLSL、kernel metadata、FP32/FP16/INT8 内核实现 | Buffer 正常执行路径 |
| `com.aiimage.inference.import.ncnn` | param/bin/PNNX 解析、参数到 IR 映射 | 业务 runner |
| `com.aiimage.inference.import.onnx` | ONNX/Sentis 图解析、opset/shape mapping | Sentis worker 作为生产后端 |
| `com.aiimage.inference.import.mnn` | MNN flatbuffer/转换产物到 IR；可先走离线转换器 | MNN native runtime 绑定为默认依赖 |
| `com.aiimage.inference.validation` | oracle 对比、层测试、模型回归、报告导出 | 发行版默认包含 |
| `com.aiimage.inference.medical` | sliding window、volume tiling、DICOM spacing、MONAI/VISTA prompt 适配 | 游戏和药物逻辑 |
| `com.aiimage.inference.game` | 摄像头/屏幕输入、帧调度、时间一致性、低延迟策略 | 医学数据 |
| `com.aiimage.inference.molecule` | 图/体素条件张量、候选批处理、GPU 保留数据协议 | 化学模型权重与私有数据 |

### 3.2 统一张量契约

将现有 `RepoVkTensorContract` 扩展为不可变 `TensorDescriptor`。任何层接收和发布的都是 descriptor + resource handle，而非裸 `RenderTexture` 或按 blob name 查询的旁表。

必须包含：

- `logicalShape`：N/C/D/H/W 或 rank-N 的真实数学 shape。
- `storageShape`：纹理宽高、array slice、Pack4 count、tile/atlas 信息。
- `layout`：`NCHW`、`NHWC`、`CDHW`、`Linear`、`Scalar`、`Packed4`；明确每维映射。
- `dataType`：FP32、FP16、INT8、UINT8、INT32；不得通过 shader 名称猜测。
- `quantization`：per-tensor/per-channel scale、zero point、axis、校准版本。
- `aliasGroup` 与 `lifetime`：只有数学视图且 storage/layout 兼容时才可 alias；否则强制生成真实 texture transform。
- `producer`、`debugName`、`modelNodeId`：报错和追踪必须定位层、blob、逻辑/物理 shape 和被拒绝路径。

`IInferenceTensor` 必须只公开 texture-native handle。缓冲区调试 oracle 单独定义 `IDebugTensorReadback`，编译期隔离，避免正式层误调用 `GetOrConvertToBuffer`。

### 3.3 CommandBuffer 为唯一调度模型

正常 `RunAsync` 应执行：编译图 -> 分配 transient Pack4 RT -> record 全图到 CommandBuffer -> submit -> GPU fence -> 提供 texture output/fence。不得逐层 `Graphics.ExecuteCommandBuffer` 或 `ReadPixels/AsyncGPUReadback`。

- 常量权重可由 immutable buffer 上传，但使用前必须 materialize 为纹理或由支持的只读权重绑定直接消费；它们不能导致中间 activation 回到 buffer。
- 临时量只从 RT/TextureArray 池分配，按 graph lifetime 重用；alias/view 优先于重排。
- 动态输入 shape 先做 CPU-side metadata specialization 和 plan cache；数据相关动态长度使用 GPU shape tensor 与 prefix/compaction 子图，不能借 readback 决定下一层。
- 异步输出由 `InferenceFence` 表达。医学可以 await，游戏按帧轮转，渲染可直接采样输出 texture。

## 4. 格式与兼容策略

### 4.1 ncnn

ncnn 是第一优先级兼容源，因为已有 parser、层实现、模型和数值基线。目标不是逐文件镜像官方 Vulkan，而是映射语义：

- 保留 ncnn `.param/.bin` 和 PNNX 导入。
- 给每个 importer 节点生成 canonical IR op，例如 `Conv2D`、`Attention`、`Resize`、`Gather`，不让后端依赖 `Ncnn*LayerRepro` 命名。
- 旧 layer 类逐步变为 importer adapter 或 kernel lowering，不再直接拥有资源管理和 fallback 决策。

### 4.2 Sentis/ONNX

Sentis 的价值是 ONNX 操作符和 Unity 用户生态兼容，不应把 Sentis worker 当作生产 fallback。策略：

- ONNX 作为长期通用模型格式；支持明确的 opset 版本并产出 model manifest。
- 保留当前 Shape/Size/Range/Where/Gather 等结构层成果，优先补 GPU shape value-flow、动态 TopK/OneHot、NonZero/Compress/GatherND/Scatter。
- `GridSample`、`RoiAlign`、`NonMaxSuppression` 放入视觉模型里程碑。
- unsupported op 必须在导入/plan 阶段给出节点名、输入 shape、缺少的 RT/Cmd/dtype 能力和替代建议；禁止执行时 placeholder。

### 4.3 MNN

MNN 主要解决移动端模型来源与量化生态。第一阶段不嵌入 MNN native execution：

1. 调查目标模型的 MNN op/量化 metadata，编写离线 `MNN -> canonical IR` 转换器或先转换为 ONNX/PNNX。
2. 以 MNN CPU/Vulkan 仅作为离线数值 oracle，用于层与模型回归。
3. 当移动端格式兼容和部署确有需求，再提供可选 native plugin adapter；该 adapter 不能替代 Unity Pack4 主路径，也不能破坏 IL2CPP/平台包体约束。

## 5. 精度与量化设计

量化必须被视为“模型契约”，而非开关。每个发布模型应附带 `ModelManifest`：输入预处理、shape profiles、布局、权重格式、activation 格式、量化参数、校准数据版本、数值阈值、目标平台和已验证 GPU。

| 模式 | 权重/激活存储 | 累积/归一化 | 首批用途 | 约束 |
| --- | --- | --- | --- | --- |
| FP32 | R32/float4 | FP32 | 数值 oracle、医学金标准、调试 | 内存/带宽最高 |
| FP16 mixed | R16/half4 | Conv/Gemm 可 FP16 输入 + FP32 或受控 FP16 accumulate；Softmax/Norm/Reduce 必须 FP32 accumulate | 默认移动/桌面视觉、游戏、部分医学 | 需逐 GPU 验证 overflow 和子正规数行为 |
| INT8 weight-only | INT8 权重 + FP16/FP32 activation | INT32 或 FP32 accumulate 后 dequant | 首个实用低内存方案 | 可避免 activation 全量量化，适合 Conv/Gemm |
| INT8 W8A8 | INT8 权重/activation，per-channel weight、per-tensor 或 per-channel activation | INT32 accumulate，requant 到纹理整数格式 | 移动端大批量视觉 | 需要完整 Quant/Dequant/Requantize 的 Cmd 实现与校准 |
| INT4 weight-only | nibble packed 权重 + FP16 activation | INT32/FP32 accumulate | 后续 transformer/大模型 | 不作为医学首发；需 GPU 位运算基准 |

实施顺序：

1. 固定 FP32 oracle：每层和模型保存随机/真实输入参考、绝对/相对误差、任务指标。
2. 交付 FP16 mixed：先完成 `Cast`、Packing、Conv/Gemm/MatMul、Softmax/LayerNorm/Reduction 的 texture Cmd 路径；归一化与 softmax 强制 FP32 累积。
3. 交付 INT8 weight-only：先针对 Conv/Gemm/InnerProduct，实现 per-output-channel scale 和纹理权重打包。
4. 再交付 W8A8 PTQ：使用代表性校准集，记录 percentile/KL/min-max 策略和层敏感度；敏感层保留 FP16。
5. QAT、INT4、稀疏和 KV-cache quantization 只在有具体模型收益证据后进入路线图。

医学模型的验收不能只用 tensor MAE：必须额外比较 Dice、Hausdorff/表面距离、labelmap mismatch 和临床关键类别漏检。游戏验证使用 FPS、P95/P99 延迟、显存、掉帧。药物模型验证使用候选有效率、排序相关性、化学合法率，不能仅比较浮点误差。

## 6. 领域产品需求与插件设计

### 6.1 AIImage：影像处理应用与引擎示范

作为 reference app，承担模型导入、模型库、对比工具和视觉模型回归：YOLO/NMS、分割、matting、CLIP、超分、CodeFormer、Stable Diffusion。优先完善 2D Conv/Gemm/attention 图，并把后处理做成 texture-first：mask、bbox、alpha、latent 不读回 CPU，只有用户导出/调试才 readback。

### 6.2 医学：MONAI/VISTA 与 JZ-Segmentation 手术导航

JZ-Segmentation 已有 DICOM/体渲染基础，且任务清单要求 CTSpine/MRSpine 的 VISTA3D 双 provider 和多标签结果。`medical` 包需提供：

- DICOM/NIfTI input adapter：spacing、orientation、rescale、窗口化和体数据 tiling。
- 3D `CDHW Pack4`、3D Conv/Deconv/Pooling/Interp、sliding-window overlap fusion、argmax/label texture 输出。
- VISTA/MONAI prompt tensor、类别标签集、multi-label mask，不将多类别压成一个二值 mask。
- 内存预算器：patch size、overlap、并发数基于显存/私有内存估算；保留 current `AIIMAGE_MONAI_*` guardrails。
- 手术导航接口：输出 3D label volume/置信度/边界距离 texture，可直接连接切割、体渲染、配准；记录模型版本、输入序列、空间变换和推理审计记录。

医学产品不能把 `ExternalPython` 与 `InternalNcnn` 的差异藏在 UI 后。两者必须使用同一 `ISegmentationProvider` 结果契约，且以 internal Pack4 路径为本地端侧发行目标，Python 仅作 oracle/过渡实现。

### 6.3 AICityRunner：游戏端 AI 推理端

该项目当前未显示既有推理包，因此应以轻量、帧预算明确的 game package 接入：

- 典型模型：视觉检测/分割、姿态、OCR、深度、环境语义、NPC 观察/embedding；优先 ONNX 和 ncnn 输入。
- `FrameInferenceScheduler`：双/三缓冲输入，N 帧一次或自适应降频，fence 未完成时复用上一帧结果，绝不能阻塞渲染主线程。
- 输入直接接受 Camera color/depth/RT，输出 texture 或 compact metadata texture；仅小型 bbox/事件在低频 readback。
- 后处理优先 GPU：NMS、tracking association、mask resize/composite。需要跨帧时保留 persistent texture state。
- 目标应按设备档位定义：PC DX12/Vulkan、Android Vulkan、必要时 Metal；每档发布 model profile，而不是运行时盲目选择精度。

### 6.4 PharmaDockingMR3：药物发现推理端

现有分析表明其 GPU 阶段被多次 CPU readback 打断，且分子语义协议存在错位。`molecule` 包首先不是加入通用神经网络层，而是建立统一 GPU 数据契约：

- 统一 C#/HLSL 原子类型、键类型、电荷、坐标、体素/热力图、候选索引和 fingerprint 的 schema。
- 蛋白结构 -> pocket/voxel condition -> 候选生成 -> fingerprint/规则筛选 -> 排序，全程保留在 GPU；只回读最终候选与用户选择的可视化数据。
- SMILES 不通过 `R16_SFloat` 纹理编码字符；使用结构化 integer texture/buffer 作为输入上传或 debug，生产中优先 token/graph tensor 的 texture-native 表示。
- 化学正确性算法（RDKit/OpenBabel、真实 Morgan、构象）可通过 optional private native/service adapter 提供；核心 engine 只负责模型 inference，不为演示式启发式算法背书。
- mesh/球棍渲染按需生成；推理输出应与结构渲染、对接评分的坐标和索引契约一致。

## 7. Git 部分开源策略

建议建立独立仓库 `aiimage-unity-inference`，采用 MIT 或 Apache-2.0（须确认第三方 shader/格式代码的许可证兼容性），并将 AIImage 作为内部集成仓库。结构：

```text
aiimage-unity-inference/          # 公共仓库
  Packages/com.aiimage.inference.*
  Samples~/VisionSandbox
  Tests~/Unit, Integration, Golden
  Tools~/Importers, Benchmark, ModelManifestSchema
  Docs~/architecture, support-matrix, contributing

AIImage/                          # 私有集成仓库
  Assets/StreamingAssets/...       # 受限模型权重、测试影像、商业资源
  Assets/Scripts/...               # 应用 UI、业务 runner、私有模型配置
  Tools/MonaiToNCNN/...            # 医学特定数据/导出/验证
```

- 开源：IR、Pack4 tensor/runtime、HLSL 内核、importer、通用测试、合成模型、基准脚本、完整能力矩阵。
- 私有：患者数据、DICOM/NIfTI 样本、MONAI/VISTA 权重/提示词资产、商业模型、模型许可受限文件、药物/蛋白数据、业务 UI 和部署密钥。
- 使用 Git subtree 或带 commit pin 的 UPM Git dependency 接入；初期推荐 subtree，便于从现有 AIImage 逐步抽取且可原子回归。
- 每个发布 tag 必须附带：支持矩阵、Unity 版本、图形 API、设备列表、性能/精度报告和模型 manifest schema 版本。

## 8. 实现阶段与验收门

### Phase 0：事实基线与防回退（1-2 周）

- 生成机器可读 `operator-capabilities.json`，逐 op/dtype/layout/RT/Cmd/quant 标注真实状态，替代文档中的主观“覆盖”。
- 新增 `StrictTextureInference` 默认开启：未具备 Cmd Pack4 路径时失败，错误包含 layer/blob/logical/storage shape/dtype。
- 将所有 buffer kernel 与 readback helper 移到 `AIIMAGE_INFERENCE_DEBUG_ORACLE` 条件程序集；CI 检查 production asmdef 不引用它们。
- 固化 CLIP、Matting、YOLO、wholeBrain probe 的 golden 输入/输出和内存上限。

验收：production runner 在日志中可证明无中间 buffer materialization；任何缺层在 plan 阶段失败；旧 buffer oracle 仍能独立做层对比。

### Phase 1：运行时内核收敛（3-6 周）

- 抽取 core/unitygpu/kernels 的 asmdef 与 UPM skeleton，保持 AIImage 行为不变。
- 完成 P0 Cmd Pack4：Conv/Depthwise/Deconv、Gemm/InnerProduct/MatMul、LayerNorm、Softmax、Reduction、Permute/Reshape，先覆盖 AIImage 与 wholeBrain 实际 shape profiles。
- 完成 texture-native 量化基础：Cast、Packing、Quantize、Dequantize、Requantize、FP16 constant/activation 绑定。
- 建立 RT pool、lifetime/alias planner、CommandBuffer fence 与 GPU profiler。

验收：wholeBrain 在 guards 开启时跑完 probe/小 patch/全量；FP32 结果不劣于当前 `run46` 基线，FP16 指标达到预先登记的医学阈值；不再由 buffer 路径救场。

### Phase 2：导入与图编排（4-8 周）

- canonical IR、shape inference、constant folding、layout/precision lowering、plan cache。
- ncnn importer 迁移到 IR；ONNX/Sentis adapter 支持静态 shape 和常见视觉图。
- 完成 GPU shape tensor 的常量/动态 value-flow；补 dynamic TopK/OneHot、NonZero/Compress/GatherND/Scatter 的确定性/冲突规则。
- 引入 model manifest、capability report CLI、导入失败报告。

验收：导入任何模型都会输出可复现 capability report；模型不支持时在导入/编译失败；Sentis worker 不进入 production execution。

### Phase 3：视觉与游戏垂域（3-5 周）

- 实现 GridSample、RoiAlign、NMS、GPU post-process 和目标 tracking data path。
- 给 AICityRunner 接入 sample：camera RT -> detector/segmenter -> overlay，双/三缓冲、无同步 readback。
- 性能基准覆盖 PC 与 Android Vulkan，给出每模型的 P50/P95/P99、显存、功耗/热降频观察。

验收：目标游戏场景内主线程无推理同步等待；GPU 未完成时策略可控且结果稳定。

### Phase 4：医学产品化（持续，5-8 周首版）

- 完成 3D Pack4 全链、sliding window fusion、multi-label output、VISTA prompt 扩展、CTSpine/MRSpine。
- 在 JZ-Segmentation 用相同 provider contract 接入本地推理，输出对接体渲染/切割/导航的 texture volume。
- 医学回归报告、内存守卫、失败恢复、审计 metadata 与离线 Unity batch 验证。

验收：CTSpine/MRSpine 的 ExternalPython 与 InternalTextureEngine 在同一测试集上输出可比的多标签结果；内部路径无 buffer fallback，资源限制触发时可控 abort。

### Phase 5：MNN 与分子工作流（4-6 周）

- MNN import feasibility matrix/离线转换和 oracle 先行，不先引入 native runtime 依赖。
- PharmaDockingMR3 建立统一原子/键/体素协议，修正筛选索引、数据源、类型映射和异步依赖。
- 形成 texture-native 条件生成/筛选的示例，最终候选才 readback；真实化学工具以可选适配器接入。

验收：端到端候选流水的中间态不回读；每一份筛选结果都有正确索引链和可追溯 schema 版本。

## 9. 面向 Codex/TRAE 的可拆任务

每个任务只修改一个包/层族/验证集，必须带 capability 状态变更和测试；禁止“顺手重构”其它层。

| 任务包 | 交付物 | 验收 |
| --- | --- | --- |
| A：严格模式 | capability JSON、strict planner、禁止 fallback 检查 | 未实现 Cmd op 明确失败；production build 无 buffer 引用 |
| B：Tensor/allocator | `TensorDescriptor`、RT pool、alias/lifetime 测试 | reshape alias 不分配；物理 transform 正确分配 |
| C：Conv 家族 | Conv/Depthwise/Deconv 2D/3D Cmd kernels 与 golden tests | FP32/FP16 对 ncnn oracle 达阈值 |
| D：Linear/attention | Gemm/MatMul/LayerNorm/Softmax/SDPA/MHA Cmd | CLIP/wholeBrain 真实小模型过图 |
| E：量化 | Cast/Packing/Q/DQ/RQ、INT8 weight-only | manifest 校准参数生效且有精度报告 |
| F：ONNX 图结构 | shape tensor、Gather/Scatter、TopK、NMS/GridSample | importer capability report 与随机 property tests |
| G：医学包 | sliding window、VISTA prompt、多标签 volume | Unity batch probe/patch/full report |
| H：游戏包 | frame scheduler、GPU postprocess、AICity sample | P95 帧时间和零同步 readback |
| I：分子包 | schema、GPU pipeline、按需 readback | C#/HLSL type contract tests，筛选索引正确 |
| J：开源治理 | UPM layout、LICENSE audit、CI、docs | 外部空 Unity 工程可安装 sample 并通过测试 |

任务提示必须提供：目标模型/shape、目标平台、精度模式、明确不可走 Buffer、golden 数据位置、成功阈值和回滚条件。对 MONAI/VISTA 任务还必须指出使用 `RunMonaiUnityDebug.bat`、10 分钟超时和既有内存 guardrails。

## 10. CI、验证与发布

- 单层：随机 shape/property test + ncnn/MNN/ONNX Runtime oracle；覆盖 Pack4 尾通道、非对齐 width、动态 batch、alias/view。
- 子图：每层发布中间 tensor hash/误差和 storage contract，定位数值偏差不依赖全模型 readback。
- 模型：vision、medical、game、molecule 四套 smoke + golden + 性能 benchmark。
- 平台：Windows DX12/Vulkan、Android Vulkan 为第一梯队；Metal/iOS 只有在 HLSL/texture 格式实际验证后标为 supported。
- 发布准入：零 strict fallback、零资源泄漏、精度门通过、P95 性能门通过、模型 manifest 完整、第三方许可证审计通过。

## 11. 近期优先级

未来两周只应推进以下顺序：

1. 建立真实 Cmd Pack4 能力矩阵和 strict 无 Buffer fallback 门禁。
2. 完成 wholeBrain 与 CLIP 实际依赖的 Gemm/MatMul/LayerNorm/Softmax/Permute/Reshape Cmd 内核，保持医疗内存守卫。
3. 抽取 `TensorDescriptor`、RT allocator 与 CommandBuffer 计划，停止在 layer 内直接决定 legacy fallback。
4. 完成 FP16 mixed 的端到端回归，再开始 INT8 weight-only。
5. 再扩展 ONNX/Sentis 图结构、视觉后处理、MNN 导入和三项目集成。

这条顺序的目的不是减少功能范围，而是先把“任何模型都能调用，但可能偷偷走 Buffer/占位”的状态，转换为“支持面可量化、失败可解释、生产路径一致”的工程基础。
