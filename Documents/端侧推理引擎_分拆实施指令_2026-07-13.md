日期：2026-07-13

## 0. 所有任务共用前置指令

把以下文字附在每个任务前：

```text

不得把 ComputeBuffer、GetBufferData、Pack4ToBufferCHW/CDHW、texture-to-buffer materialization，或“先算 Buffer 再转回纹理”作为正常模型执行的回退。缺少 Pack4 RT/Cmd 能力时，在严格模式中明确失败，报错必须包含 layer/node、blob、logical shape、storage shape、layout、dtype 和被拒绝的 fallback。

2. 运行最小的真实 Unity 验证或单元/编辑器测试；
3. 说明改动文件、验证结果、仍不支持的 shape/dtype/分支；

```

## 2. 可独立派发的具体指令

### A1：生成真实算子能力矩阵与模型预检

```text
实现一个机器可读的 operator capability matrix，准确描述当前引擎每个 canonical/ncnn/Sentis 算子的真实能力，供导入和执行计划预检使用。

范围：新增或修改 core/metadata、NcnnLayerFactoryRepro 相关注册元数据、Editor/CLI 报告工具和测试。不要实现新算子，不要修改任何数值 kernel。

能力条目至少包含：operator 名称、import 支持、shape inference、RT、CommandBuffer、FP32、FP16、INT8、layout、rank、已验证模型、状态（supported/partial/alias-only/debug-only/unsupported）和限制说明。partial 不能被 planner 当作 supported。导出稳定 JSON，例如 operator-capabilities.json。

实现模型预检：针对已加载模型图输出缺失节点、参数、输入 logical/storage shape、目标 backend/dtype 和推荐动作。预检不得执行模型，更不能因检查而 materialize 到 Buffer。

验收：用当前 YOLO、CLIP、wholeBrain 任一模型生成报告；报告中将 Gemm/LayerNorm 等实际 Cmd 占位分支列为 partial/unsupported，而不是 supported；新增 C# 测试验证 JSON schema 和 strict 判定。
```

### A2：生产路径 Buffer 审计与 Debug 编译隔离

```text
审计并隔离 AIImage 正常推理中的 ComputeBuffer 回退和 texture-to-buffer materialization。目标是建立可自动检查的边界，而不是立刻删除所有 legacy oracle。

范围：NcnnCompute、NcnnLayers、asmdef/编译符号、Editor validation。不要改 layer 数学实现。

识别 GetBufferData、GetOrConvertToBuffer、Pack4ToBufferCHW/CDHW、TexToBuf、BufToTex、ExecuteComputeBufferPath 等调用。把合法的 baseline dump、数值对照、固定输入上传标注为 Debug/Oracle；生产调用点改为明确拒绝或走现有 texture 路径。新增 AIIMAGE_INFERENCE_DEBUG_ORACLE 编译开关或等价的程序集边界，确保 production asmdef 无法引用 debug readback API。

验收：提供审计清单；新增静态测试或脚本，production 目录出现禁止 API 调用即失败；现有 debug compare 仍可编译；正常 runner 的日志可证明没有中间 Buffer materialization。
```

### A3：Golden 数据、数值回归与中间张量诊断

```text
建立独立的推理 golden 回归框架，覆盖单层、子图和真实模型。目标是让 Pack4 RT/Cmd 的每次改动可量化验证，而不是只比较最终图片。

范围：Tests~/或现有 Editor test、Tools 验证脚本、golden manifest、报告格式。不得修改生产内核。

支持：输入 fixture、期望输出、FP32 oracle、FP16/INT8 阈值、绝对/相对误差、任务指标、平台信息。对子图按指定 blob 采样，走 texture-aware debug readback；该 readback 必须明确在 Debug/Oracle 测试中。先接入 CLIP、Matting、YOLO 小样本和 wholeBrain probe 的 manifest，不复制受限患者数据。

验收：单命令产生 JSON/Markdown 报告；故意扰动一个已知 tensor 能让测试失败并定位 node/blob；报告包含 logical/storage shape 和 dtype；不影响 production package 依赖。
```

### A4：开源 UPM 包骨架与许可证清单

```text
设计并落地最小可编译的 Unity UPM package 骨架，准备从 AIImage 抽取端侧推理核心。

范围：在仓库内新增 Packages/com.aiimage.inference.core、unitygpu、kernels、validation 的 package.json、asmdef、README、CHANGELOG、LICENSE/NOTICE 模板、Samples~ 空目录或最小 sample。不要迁移现有运行时代码，不要移动私有模型或数据。

核心包只定义稳定 namespace、接口和依赖方向：core 不依赖 Unity 场景；unitygpu 依赖 core；kernels 依赖 unitygpu；validation 不能被 production package 依赖。列出目前待审计的 ncnn、Sentis、MNN、MONAI、第三方 HLSL/模型许可证来源。

验收：空 Unity 工程可通过 file dependency 引用 core；所有 asmdef 无循环依赖；README 明确 public/private 边界；不改变现有 AIImage 编译行为。
```

### B1：TensorDescriptor 与纹理原生张量契约

```text
将现有 RepoVkTensorContract 发展为统一的 TensorDescriptor/IInferenceTensor 契约，并在最小范围内接入现有 texture/cmd tensor 发布和读取。

范围：Assets/Scripts/NcnnCompute/RepoVkTensor.cs、NcnnRepro.cs 相关 contract helper、必要测试。不要同时改具体算子 shader。

descriptor 必须不可变或发布后不可修改，包含 logicalShape、storageShape、layout、Pack4 信息、dtype、quantization metadata、alias group、lifetime、owner、producer/node/blob/debug name。所有 texture alias 保持 owner 生命周期；只有 storage 布局兼容时允许 alias。禁止使用名字旁 shape 字典作为事实来源。

为不兼容 alias 的场景提供明确错误或后续真实 transform 的需求标识，绝不退到 Buffer。错误需给出原/目标 logical 与 storage shape。

验收：reshape/squeeze/flatten 的兼容视图不创建新 RT；一个不兼容例子被拒绝或标为必须 transform；CLIP 或 Matting 最小路径仍工作；新增 alias 生命周期和 descriptor 不可变性测试。
```

### B2：CommandBuffer/Pack4 RT 临时资源生命周期管理

```text
实现或重构 CommandBuffer 使用的 Pack4 RenderTexture/TextureArray 临时资源生命周期管理，替代任何正常执行中的临时 ComputeBuffer 分配。

范围：NcnnCompute 临时 RT 管理代码、CommandBuffer 计划执行辅助代码、资源 tracker 与测试。不要引入或保留 temp pool/RT pool；不要改变具体 layer 数学。

推理阶段的临时纹理必须全部使用 Unity 及 CommandBuffer 提供的临时 RT 接口创建和释放（例如 CommandBuffer.GetTemporaryRT/ReleaseTemporaryRT，或与当前 Unity 版本等价的命令缓冲区临时 RT API）。command buffer路径临时推理的应该使用现有Compute Texture封装的ommandBuffer.GetTemporaryRT / ReleaseTemporaryRT，pack4 rt路径的rendertexture和command buffer路径的Compute Texture，通过rent等接口最终应该调用Unity和command buffer的临时接口，而不能自行池化管理；不得自行维护跨节点、跨 dispatch、跨帧或跨 CommandBuffer 的 temp pool、RT pool、空闲列表、缓存复用或手工 RenderTexture 分配。

临时 RT 描述必须由 TensorDescriptor 的 storageShape、graphics format、array depth 和 random write 派生；资源 tracker 只负责记录 create/release、resource owner/node、逻辑与存储 shape、估算峰值临时显存和未释放诊断，不得据此复用或重新分配资源。不能在 CommandBuffer 内尝试创建任意临时 ComputeBuffer。持久输入、输出和经 descriptor 验证的兼容 alias 不属于临时 RT；alias 不得绕过临时 RT 的创建/释放规则。

验收：构造含分支和不同生命周期的测试计划，证明每个中间值都通过 Unity临时 RT API/command buffer临时RT API 创建，并在其最后一次使用后释放；验证不存在 temp pool/RT pool、手工临时 RenderTexture 分配、临时 ComputeBuffer 或跨帧缓存复用；运行一个真实 Cmd 子图时 tracker 显示完整 RT 创建/释放配对且无临时 Buffer；发生预算不足时错误含需求大小、当前峰值和节点名。
```

### B3：严格 Texture 执行计划与失败诊断

```text
在模型编译/执行计划阶段实现 StrictTextureInference。默认生产模式下，模型中任一节点未拥有目标 dtype/layout 的 CommandBuffer Pack4 真实实现时，必须在 dispatch 前失败。

范围：NcnnRepro/图计划、能力矩阵消费、错误类型、Editor/CLI 测试。不要实现新 shader。

严格模式不得接受 alias-only、placeholder、materialize-from-buffer、legacy path 作为算子计算能力；纯 view/noop/split 可通过，但必须有 descriptor alias 证据。支持 DebugOracle 模式显式放宽，但该模式不能由 production runner 默认启用。

验收：对一个已知不完整层（例如通用 LayerNorm/Quantize 分支）在 plan 阶段失败，错误包含全部诊断字段；对纯 reshape/split 图成功；对一个已验证 Pack4 图成功；单测覆盖 strict/relaxed 两种模式。
```

### C1：2D Conv/Depthwise/Deconv 的通用 Cmd Pack4 收敛

```text
补齐并收敛 2D Convolution、ConvolutionDepthWise、Deconvolution、DeconvolutionDepthWise 的 CommandBuffer Pack4 真实路径，优先覆盖 AIImage 现有模型实际使用的 shape profiles。

范围：相应 Ncnn*LayerRepro.cs、Pack4Conv HLSL kernel group、kernel binding/dispatch、该层 golden tests。不要更改 3D 卷积、Gemm 或全局 allocator。

支持的分支必须显式声明：kernel/stride/dilation/pad/group/bias/activation、输入输出 pack 和 tail channel 行为。无法支持的参数在 strict mode 失败，不能回 Buffer。权重可以是 immutable upload source，但 activation/intermediate/output 必须是 texture-native。执行通过 CommandBuffer，禁止逐层立即执行和 CPU readback。

验收：与 ncnn oracle 的 FP32 层测试覆盖普通、depthwise、group、stride>1、非 4 对齐通道；FP16 测试只在已实现时声明；跑一个 YOLO 或 Matting Cmd 子图并显示无 buffer fallback。
```

### C2：3D Conv/Deconv/Pooling/Interp 的医疗 Cmd Pack4 收敛

```text
补齐 MONAI/VISTA 实际依赖的 3D Convolution、Deconvolution、Pooling、Interp 的 CommandBuffer Pack4 CDHW 路径。保持 wholeBrain 的内存安全基线。

范围：NcnnConvolution3DLayerRepro、NcnnDeconvolution3DLayerRepro、NcnnPooling3DLayerRepro、NcnnInterpLayerRepro 相关 CDHW 分支与 Pack4Spatial/Conv kernels；不要修改 2D layer。

logical CDHW 与 texture array/storage mapping 必须由 TensorDescriptor 驱动。支持的 shape profile、pad/stride/dilation/align_corners 写入 capability metadata。中间 patch 只能分配 Pack4 RT/TextureArray；任何缺分支 strict 失败。不得关闭或削弱 MONAI 内存守卫。

验收：先执行 RunMonaiUnityDebug.bat 的 probe_only 或 max_patches=1；再小 patch compare；最后才允许全量。报告对比 run46 基线的 labelmap、内存峰值、资源 tracker 和失败诊断。默认超时 10 分钟。
```

### C3：Gemm/MatMul/LayerNorm/Softmax/Reduction/Attention Cmd Pack4

```text
实现 AIImage 和 wholeBrain 实际需要的纹理原生 CommandBuffer 线性与注意力算子：Gemm、MatMul、InnerProduct、LayerNorm、Softmax、Reduction，以及其调用的 SDPA/MHA 子路径。

范围：对应 NcnnLayers、NcnnKernels.Pack4Matmul.hlsl、NcnnKernels.Pack4PointwiseNorm.hlsl、绑定和金标准测试。不要修改卷积家族或导入器。

要求：输入/输出均为 Pack4 或明确的 LinearMat texture；执行不得 materialize 到 Buffer。Softmax、LayerNorm、Reduction 的归约精度默认 FP32 accumulate，即便输入为 FP16。明确支持 axis、transpose、broadcast、mask、causal 和无 kv-cache 的边界；kv-cache 未实现时 strict 失败。

验收：矩阵随机测试覆盖非对齐维度、batch、transpose；attention 小图与 ncnn/oracle 对比；CLIP 和 wholeBrain 的最小真实子图通过；输出报告记录误差、形状、dtype、峰值 RT 使用量。
```

### C4：布局、视图与真实 transform 的 Cmd Pack4 完整性

```text
完成 Reshape、Flatten、Squeeze、ExpandDims、Permute、Slice、Tile、Packing、Cast 的 CommandBuffer Pack4 语义。重点是正确地区分可 alias 的 view 与必须做 texture transform 的情况。

范围：这些 layer 的 C#、Pack4Layout HLSL、测试和 capability metadata。不要改 Conv 或 attention。

每个分支必须验证 logicalShape/storageShape/layout；identity/view 走 descriptor alias，非 identity 的 transpose/tile/pack/cast 走真实 Pack4 texture kernel。RT/Cmd 不能把数据转成 buffer。shape 参数来自静态 metadata 或 texture shape tensor；不支持数据相关长度时 strict 失败。

验收：给出 alias/no-alias 的单测矩阵；随机 tensor 的 Permute/Slice/Tile 与 oracle 对比；现有 CLIP reshape/attention path 通过；报告不再将 Tile、Flatten、Rotary 的 placeholder 标为可生产使用。
```

### D1：FP16 mixed precision 模式

```text
实现可由 ModelManifest 驱动的 FP16 mixed precision 执行模式。目标是实际降低 activation/weight 带宽，同时保护数值敏感的归约。

范围：dtype metadata、texture format/packing、Cast、内核精度选择、manifest、golden/benchmark。不要在本任务内实现 INT8。

规则：FP16 tensor 使用兼容的 half4 texture storage；Conv/Gemm 可在已验证 kernel 中使用 FP16 输入/权重；LayerNorm、Softmax、Reduction、概率/指数相关路径必须 FP32 accumulate，输出按 manifest 决定 cast。不得把 FP16 转 Buffer 再计算。未实现的 op/dtype 组合在 strict plan 失败。

验收：同一模型的 FP32 与 FP16 manifest 可切换；CLIP/Matting/医学 probe 中至少各一个合适模型有误差及任务级指标报告；报告含显存峰值和耗时；没有 silent FP32/Buffer fallback。
```

### D2：INT8 weight-only 纹理原生推理

```text
实现第一阶段 INT8 weight-only 推理，优先为 Conv/Gemm/InnerProduct 提供每输出通道量化权重、scale 和纹理原生反量化/累积。

范围：ModelManifest quantization schema、权重导入打包、相关 kernel、能力矩阵、校准/回归工具。不要试图在同一任务实现 W8A8。

权重可作为 immutable packed upload source；activation 与中间输出维持 FP16/FP32 Pack4 texture。实现 per-output-channel scale，指定对称/非对称策略和版本；累积精度明确。禁止通过 buffer 临时展开 INT8 权重后执行。缺少对应 kernel 的节点在 strict quant plan 失败。

验收：选定一个 Conv 模型和一个 Gemm/CLIP 子图，比较 FP32、FP16、INT8 weight-only 的模型/层误差、包体权重大小、RT 显存和耗时；manifest 中记录校准/量化版本；所有数字可复现。
```

### D3：ONNX/Sentis 动态 Shape 与索引图算子

```text
扩展 ONNX/Sentis importer 和 Pack4 texture backend，优先实现动态 shape value-flow，以及 NonZero、Compress、GatherND、ScatterElements/ScatterND/Scatter、动态 TopK/OneHot 的可生产子集。

范围：ONNX/Sentis adapter、canonical IR shape tensor、SentisOps HLSL、capability/tests。不要修改 ncnn 数值层。

数据相关输出长度必须使用 GPU shape tensor、prefix sum/compaction 或明确的容量/overflow 规则；不能 readback 到 CPU 以决定下游 shape。Scatter 必须定义冲突写入语义（例如 last-write、atomic reduction 或直接拒绝不确定图），并在 capability 中公开。每个已支持子集有 rank/axis/dtype 限制。

验收：构建随机 property tests 与 ONNX Runtime/Sentis oracle 对照；动态结果的 tensor contract 正确；不支持的冲突/dynamic case 在 plan 阶段给出可操作错误；全程无 buffer fallback。
```

### D4：视觉后处理与 AICityRunner AR 结果数据通路

```text
实现视觉模型的 texture-native 后处理基础：GridSample、RoiAlign、NonMaxSuppression 的明确支持子集，并设计可供 AICityRunner 的 AR 图像识别、姿态识别和手势识别消费的 GPU 输出协议。以已核验的 GitHub 模型作为 fixture：`yolov8n`/`yolov8n_cls`、`MoveNet Lightning`、`yolov8n_pose` 和 PINTO ONNX 手势链。

范围：新 canonical op/layer、Pack4/Linear texture kernels、game package adapter 或 sample；不要修改 AICityRunner 的业务场景逻辑。

fixture 来源与约束：`Tencent/ncnn` 的 `examples/yolov8_pose.cpp` 定义 YOLO pose 的 640 输入、17 个三元关键点和 NMS 参考语义；`nihui/ncnn-android-yolov8` 提供 ncnn 参数/权重格式样本；`FeiGeChuanShu/ncnn_Android_MoveNet` 提供 MoveNet Lightning ncnn 样本；`PINTO0309/hand-gesture-recognition-using-onnx`（Apache-2.0）提供 192x192 palm detector、224x224 landmark 和 keypoint MLP。未声明许可证的社区权重仅作内部 fixture，不能随 Player/Sample 发布；发行模型必须在 manifest 中锁定合法来源、SHA-256 和许可。

NMS 输出使用固定容量的 texture-native metadata/indices，并定义 overflow 规则；不得为动态检测数回读 CPU 后再执行后处理。输入接受调用方提交的 AR Camera/Camera RenderTexture；输出定义图像分类、bbox/mask、姿态/手势关键点与置信度的 GPU 结果，以及显式的模型空间到相机/AR 世界空间变换。MoveNet heatmap/offset top-1、YOLO pose 关键点解码、palm ROI 的 `GridSample` crop 和 landmark->MLP 归一化均须在 GPU 完成。所有 kernel 支持范围进入 capability matrix。不要引入 `FrameInferenceScheduler`、帧率控制、双/三缓冲或跨帧跟踪。

验收：在独立 Unity sample 中完成 AR Camera RT -> `yolov8n_cls` 或自训 `yolov8n`、MoveNet Lightning、PINTO hand chain -> GPU 后处理/overlay；`yolov8n_pose` 作为多人扩展 fixture。对每个模型先输出 import/strict capability report，缺少 Cmd op 时失败；Frame Debugger/日志证明没有同步 readback；列出面向 AICityRunner 的一次请求、异步完成和结果坐标转换 API，不包含帧调度 API。
```

### E1：MONAI/VISTA 医学执行插件与 JZ-Segmentation 接入契约

```text
实现医学领域 package 的最小可用接口，使 InternalTextureEngine 与 ExternalPython provider 使用同一分割结果契约，并为 JZ-Segmentation 的 CTSpine/MRSpine VISTA3D 多标签任务准备接入。

范围：medical package/interfaces、AIImage MONAI runner adapter、JZ-Segmentation 可复制的 provider contract 文档或 package；不改底层卷积/attention 数学内核。
```
