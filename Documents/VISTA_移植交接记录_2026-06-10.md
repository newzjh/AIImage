## 对 VISTA 的判断

- `vista3d` 不是简单的单输入单输出自动分割 bundle，它带 prompt 语义，至少支持 label prompt，也支持 point prompt。
- 仓库当前最成熟的是“固定输入体数据 + fixed network + sliding window + 后处理 + baseline compare”这条自动分割路径。
- 因此 VISTA 线程第一步不要急着做完整 interactive prompt 体系，建议先把最小闭环拆成：
  1. 明确要先移植 `vista3d` 还是 `vista2d`
  2. 优先尝试 `vista3d` 的 label prompt 自动分割最小路径
  3. 暂时不做 point prompt UI，先做固定 prompt 的 baseline / dump / compare

## 推荐起步顺序

1. 先确认目标是 `vista3d` 还是 `vista2d`。
2. 如果是 3D 医学分割主线，优先做 `vista3d`。
3. 直接读取 `vista3d/configs/inference.json`，梳理：
   - 网络定义
   - 输入键
   - prompt 相关输入
   - 后处理输出
4. 判断当前 `Tools\MonaiToNCNN` 的导出链是否已经能导出该 bundle 的网络主体。
5. 如果导出链能出 param/bin，优先把“固定 prompt 的推理最小闭环”接到 `MONAINcnnReproRunner` 风格的 runner 上。
6. 先做 baseline dump、tensor dump、summary、runtime log，先复用已有 wholeBrain 的调试资产格式。

## 需要特别注意

- 当前 AIImage 仓库已经明确偏向 pack4 `RenderTexture` 主路径，不要把新工作主要堆到 legacy compute buffer 路径上。
- 但 VISTA 初期如果只是为了打通 correctness，允许先借现有 buffer fallback 做局部验证。
- Unity batch 调试统一优先用：
  - `E:\Projects\AIImage\Tools\MonaiToNCNN\RunMonaiUnityDebug.bat`
  - 默认 Unity: `C:\Program Files\Unity 6000.2.7f2\Editor\Unity.exe`
  - 默认 timeout: 10 分钟
- 任何可能导致显存爆掉或机器重启的试验，不要直接全量跑：
  - 先 probe
  - 先限制 patch 数
  - 保持内存守卫开启
